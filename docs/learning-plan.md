# 六周入门计划

每周建议投入 8～12 小时。不要只看教程，每个任务都必须形成一个可检查的提交。

## 第 1 周：Git、GitHub 与项目边界

- [ ] 理解工作区、暂存区、本地提交、远程仓库的区别；
- [ ] 掌握 `git status`、`git diff`、`git add`、`git commit`、`git log`；
- [ ] 创建 GitHub 仓库并完成第一次 push；
- [ ] 理解 `.gitignore`，确认数据和权重不会进入版本库；
- [ ] 在 `docs/research-log.md` 写下第一周学习记录。

验收：GitHub 上能看到本仓库，至少有两个语义清晰的提交。

## 第 2 周：YOLO 数据格式与数据质量

- [ ] 理解边界框的 `xywh` 与 `xyxy` 表示；
- [ ] 理解归一化坐标及其反变换；
- [ ] 运行合成数据生成与校验命令；
- [ ] 手动修改一个非法标签，观察校验器如何报错；
- [ ] 统计目标尺寸分布，理解 COCO 的小、中、大目标阈值。

验收：能独立解释一条 YOLO 标签的五个字段。

## 第 3 周：训练、验证与误差分析

- [ ] 完整运行一次 CPU 烟雾训练；
- [ ] 找到 loss 曲线、混淆矩阵、PR 曲线；
- [ ] 解释 Precision、Recall、mAP50、mAP50-95；
- [ ] 用测试集重新评估，不混用验证集与测试集；
- [ ] 记录失败样例，并给失败原因分类。

验收：能区分训练集、验证集、测试集的职责。

## 第 4 周：真实数据集

- [ ] 与导师确认一个真实数据源和使用许可；
- [ ] 编写或使用数据集转换脚本；
- [ ] 生成数据统计和抽样可视化；
- [ ] 跑通 YOLO 基线并保存配置；
- [ ] 固定随机种子，重复一次实验检查稳定性。

候选数据源：VisDrone、DOTA、xView、PCB Defect、NEU-DET、自建数据。最终选择必须以导师意见和数据许可为准。

## 第 5 周：单一改进与消融实验

- [ ] 只选择一个变量，例如 P2 检测头、切片推理、注意力或损失函数；
- [ ] 写明假设、实现方式和预期变化；
- [ ] 保持数据划分、训练轮数和评价协议一致；
- [ ] 完成 baseline、treatment、ablation 三组实验；
- [ ] 不只报告最好结果，也报告失败与不稳定现象。

验收：每个结论都能追溯到配置、日志和指标。

## 第 6 周：开源发布与论文准备

- [ ] 补齐 README、安装说明、复现命令和结果表；
- [ ] 将关键版本打上 Git tag 并创建 GitHub Release；
- [ ] 检查没有提交数据、密钥、权重和私人信息；
- [ ] 整理消融表、可视化和限制分析；
- [ ] 和导师确认是否能形成论文投稿。

验收：陌生人在一台新机器上能按 README 复现结果。
